# Security Policy

## Supported versions

Security fixes are made for the current `main` branch and the latest published
version of each public npm package. Earlier releases are not supported.

## Reporting a vulnerability

Do not report suspected vulnerabilities in public issues, pull requests,
discussions, or social media. Report them privately to
[security-opentwin@opening.science](mailto:security-opentwin@opening.science).

Include a clear description of the issue, affected package and version, impact,
and steps to reproduce it. Use a minimal, sanitized reproduction.

Do not include health payloads, patient identifiers, access tokens, passwords,
credentials, raw API responses, or other sensitive data in a report. Describe
the data shape or provide synthetic data instead.

## What to expect

The maintainer will acknowledge reports within five business days and provide a
status update after initial triage. Valid reports are assessed, remediated, and
disclosed in coordination with the reporter when practical. Remediation timing
depends on severity, affected users, and the availability of a safe fix.

Please keep the report confidential until a fix or coordinated disclosure is
agreed. The project may publish an advisory and release notes once users can
protect themselves.
