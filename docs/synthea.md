# Synthea cohort generation

Synthetic FHIR R4 patients for local Route B work (structured FHIR at build
time). Inventory of Anchor LOINC coverage lives in
[findings/synthea-coverage.md](findings/synthea-coverage.md) — this document is
only the **generator recipe**.

## Why the cohort is not committed

N=100 Synthea FHIR patients are hundreds of megabytes, unreviewable as diffs,
and go stale when config changes. The repo stores a pinned JAR checksum, export
config, fixed seeds and dates, and a generation script. Anyone with Java 21+
can reproduce the same patient files from the recorded seeds and dates.

Optional distribution of a pre-built N=100 artifact (GitHub Release vs Git LFS)
is a maintainer decision — not part of this recipe.

## Generate

```bash
./tools/synthea/generate.sh
```

Defaults: Synthea **v4.0.0**, seed **42**, clinician seed **43**, N=**100**,
Massachusetts, reference and end date **20260101**, FHIR R4 only. Output:
`tools/synthea/out/` (gitignored), plus `out/manifest.json` with seeds, dates,
version, config hash, and patient file count.

Override with `SYNTHEA_POPULATION`, `SYNTHEA_SEED`, `SYNTHEA_CLINICIAN_SEED`,
`SYNTHEA_STATE`, `SYNTHEA_REFERENCE_DATE`, `SYNTHEA_END_DATE` (dates as
`YYYYMMDD`).

Optional cohort filters, all off by default:

| Variable | Synthea flag | Meaning |
|---|---|---|
| `SYNTHEA_AGE` | `-a` | `MIN-MAX` age on the reference date, e.g. `40-75` |
| `SYNTHEA_GENDER` | `-g` | `M` or `F` |
| `SYNTHEA_CITY` | city argument | a city Synthea knows in `SYNTHEA_STATE` |
| `SYNTHEA_KEEP_MODULE` | `-k` | keep module JSON; only people it keeps are written |
| `SYNTHEA_MODULES_DIR` | `-d` | extra modules, e.g. Synthea Module Builder exports |
| `SYNTHEA_OUT_DIR` | `exporter.baseDirectory` | output folder instead of `tools/synthea/out/` |

The output folder is deleted and recreated on every run, so the script refuses
a folder that holds anything it did not write. With a keep module or modules
folder, the manifest records `keepModuleSha256` and `modulesDirSha256` (a hash
over file contents and relative names) and the output folder gets copies
(`keep-module.json`, `modules/`), so the folder alone is enough to rerun it. The
manifest also records `city`, `age`, `gender` and `fhirContentSha256`, the
checksum below.

## Reproducibility

The same seeds, dates, population, state and Synthea version give the same
patient files, byte for byte, in any folder and any time zone. The dates matter:
without them Synthea simulates up to the moment the run starts, so two runs of
the same seed differ by however far apart they started. The script passes `-r`
and `-e` and runs Java in UTC, because Synthea reads the dates in the JVM's time
zone.

`synthea.properties` also sets `generate.thread_pool_size = 1`. With several
generator threads, Synthea v4.0.0 has a race: repeated runs of the same seed
differ in a few fields (seen as a missing allergy reaction severity in one of
100 patients). One thread is slower, so for large cohorts run several batches
in parallel instead.

To check two runs match, compare:

```bash
cd tools/synthea/out/fhir && sha256sum *.json | sort | sha256sum
```

`configHash` in the manifest covers the contents of `synthea.properties` and
`version.lock`, so it is the same in every checkout.

## Large cohorts in batches

Larger cohorts are generated as batches of 10,000, one seed pair per batch so no
patient repeats, each stored as one `tar.zst` (FHIR JSON compresses about 45×).
The recipe used so far is 100 batches: seeds 1001–1100, clinician seeds
2001–2100, giving 1,000,000 living patients (about 1.15 million records with the
deceased) and about 860 MB compressed per batch.

`generate.sh` writes to `tools/synthea/out/` and clears it first unless
`SYNTHEA_OUT_DIR` names another folder; give each parallel batch its own
`SYNTHEA_OUT_DIR`. Sequentially, stopping at the first failure so a partial
batch is never archived:

```bash
set -euo pipefail
for i in $(seq 1 100); do
  SYNTHEA_POPULATION=10000 SYNTHEA_SEED=$((1000 + i)) SYNTHEA_CLINICIAN_SEED=$((2000 + i)) \
    ./tools/synthea/generate.sh
  name=$(printf 'batch-%03d' "$i")
  cp tools/synthea/out/manifest.json "$name.manifest.json"
  tar -C tools/synthea/out -cf - fhir | zstd -T0 -10 -o "$name.tar.zst"
done
```

Keep the default dates, or set both date variables to the same value for every
batch and record them.

## Cohorts generated before fixed dates

These were made with the script before it passed fixed dates and used one
thread, so they cannot be regenerated byte for byte. Their manifests do not
record the dates, and their `configHash` values depend on the folder they were
generated in:

- The 10,000-patient reference cohort: seed 42, clinician seed 43, generated
  2026-10-24, 11,551 records, content checksum
  `f918035848aed656e4d573197cc616f4948d2106a0bb368dd629a54dadbc06c2`.
- The 1,000,000-patient batches: seeds 1001–1100, clinician seeds 2001–2100,
  generated 2026-10-24 to 2026-10-25.

A rerun with the same seeds produces the same patients with every timestamp
shifted, and a slightly different set of deaths near the end of the simulation.

## Cohort Studio

[`tools/cohort-studio/`](../tools/cohort-studio/README.md) is a local web app on
top of `generate.sh` (`pnpm studio`, then http://127.0.0.1:4400). A researcher
picks population, place, ages, sex, dates and seeds, and clicks conditions
together from a list read out of the JAR's own modules; the studio turns them
into a keep module ("any of" or "all of"). Custom Module Builder modules can be
added. The result is a recipe file with every input, the Synthea version, JAR
and settings hashes and the keep-module and custom-module hashes. Each run goes
through `generate.sh` into its own folder, and a finished run can be explored
in the browser.

`pnpm cohort <recipe.json>` reruns a recipe without the page, and
`pnpm --filter @open-twin/cohort-studio repro` checks that one recipe run three
times gives identical patient files. All people it produces are synthetic.

## CI without Java

`packages/fhir-r4/src/tests/fixtures/synthea/` holds three trimmed patient
bundles so fixture tests run without downloading Synthea or requiring a JVM.
