# Connector registry

`registry/connectors.json` is the single source of truth for which connectors exist
(decision [D16](../DECISIONS.md#d16); spec [section 5.B](specs/reader-architecture.md)).
It sits at the repository root so tools outside TypeScript can read it, and
`registry/connectors.schema.json` is its JSON Schema, generated from the zod schema in
`packages/reader-core/src/registry.ts`.

The table below is generated. Edit `registry/connectors.json`, then run
`pnpm exec tsx scripts/generate-registry-docs.ts`; `pnpm verify` fails while it is stale.

## How to read it

- **id** equals the `connector` code in `Bundle.meta.tag`, so existing bundles stay
  traceable. An **alias** records naming history only and is never a second id.
- **priority**: the delegating reader asks higher priorities first. `fhir-r4` sits last
  because it accepts any FHIR Bundle.
- **status** is `must-have`, `nice-to-have`, `research` or `deprecated`.
- **reader** names the class the package exports once its adapter exists; `pending`
  means the connector's existing entry points are the only way in for now.
- **dataTypes**, in `connectors.json`, are the request types a reader accepts. They are
  spelled as the code spells them: Oura's `vO2_max` and `daily_cardiovascular_age` are
  the vendor's scope names, and WHOOP always fetches `recovery`, `cycle` and `sleep`.

## Google Health and Fitbit

`google-health` carries the alias `fitbit`. The package calls `health.googleapis.com/v4`,
which Google documents as the next generation of the Fitbit Web API; its error catalogue
includes `ACCOUNT_NOT_LINKED` for a Google account with no linked Fitbit account. A request
for `fitbit` therefore reaches the same reader. It is not Google Health Connect, which is
an on-device Android API with no cloud surface.

## VITRONIC authentication

BodyLoop takes either a username and password, exchanged as an OAuth 2.0 password grant
at the token endpoint, or a pre-issued API token; every data call then sends a bearer
token. The entry says `oauth2` because that is how a host obtains credentials; the token
path is the same bearer without the exchange.

## Adding a connector

1. Add the entry to `registry/connectors.json`. Every path in it must exist.
2. Register the package's verification bundle in `verify/bundles.manifest.ts`.
3. Run `pnpm exec tsx scripts/generate-registry-docs.ts` and commit the generated files.
4. When the adapter lands, set `export` to the reader class; `verify/check-registry.ts`
   then checks that the reader's `descriptor` equals the entry.
